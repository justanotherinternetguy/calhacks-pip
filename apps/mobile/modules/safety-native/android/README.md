# SafetyNative — Android

Kotlin side of the `SafetyNative` Expo module: persistent sensing service, night-mode controller,
check-in / alarm UI, location escrow, and Supabase uploads. All detection runs in the Rust core
(`core/crates/safety-ffi`, exposed through uniffi as package `uniffi.safety`).

## Build steps

1. **Rust core → `.so`** (from `core/`):
   ```sh
   cargo install cargo-ndk
   rustup target add aarch64-linux-android x86_64-linux-android
   cargo ndk -t arm64-v8a -t x86_64 -o ../apps/mobile/modules/safety-native/android/src/main/jniLibs \
     build --release -p safety-ffi
   ```
   Produces `jniLibs/arm64-v8a/libsafety_ffi.so` and `jniLibs/x86_64/libsafety_ffi.so`.
2. **Kotlin bindings** (uniffi 0.29, proc-macro mode, library-based generation):
   ```sh
   cargo run -p safety-ffi --bin uniffi-bindgen -- generate --library \
     target/aarch64-linux-android/release/libsafety_ffi.so --language kotlin \
     --out-dir ../apps/mobile/modules/safety-native/android/src/main/java
   ```
   Writes `java/uniffi/safety/safety.kt` (`core/build-mobile.sh` does the same from a host build of the
   library). The bindings call `Native.load("safety_ffi")` through JNA (`jna:5.14.0@aar`), which resolves
   to `jniLibs/<abi>/libsafety_ffi.so` — the `[lib] name` in `core/crates/safety-ffi/Cargo.toml` must stay `safety_ffi`.
   Generated names: records/enums/`SafetyEngine` as in Rust, functions camelCase (`deriveHourKey`), enum
   variants SCREAMING_SNAKE (`UserAction.MANUAL_SOS`), errors `CryptoException.Failed` / `EngineException.Config|Baseline`,
   `u64`→`ULong`, `u32`→`UInt`, `u8`→`UByte`, `Vec<u8>`→`ByteArray`.
3. **YAMNet assets**: download the TFLite YAMNet from TF Hub / Kaggle (`yamnet.tflite`, ~4 MB, input
   `[15600]` float32 @ 16 kHz, output 0 = 521 scores) and its `yamnet_class_map.csv` into
   `src/main/assets/`. `YamnetClassifier` resolves the Screaming / Shout / Yell / Glass / Shatter indices by
   name from the CSV so a re-exported model cannot silently shift them. Without the asset the audio
   booster is simply disabled; the model works without it.
4. `core/build-mobile.sh` is expected to run steps 1–2; `model-v1.toml` is copied into assets by the
   `copyModelConfig` Gradle task.
5. The app's Expo config plugin must add the permissions and the `foregroundServiceType` declaration to the
   app manifest (this module declares them too with `tools:node="merge"`), and request the
   `FOREGROUND_SERVICE_LOCATION|MICROPHONE|SPECIAL_USE` Play declarations.

## Runtime rules worth knowing

- **Boot without mic.** Android 14+ refuses to start a microphone-type foreground service from the
  background. `BootReceiver` restarts `SensingService` with `allowMic=false` and posts a "tap to re-arm"
  notification. Opening the app calls `configure`, which restarts the service with `allowMic=true`; the
  microphone type is only added to the service when a night session starts.
- **Pre-permission start.** Before the location permission is granted, the service runs as `specialUse`
  (Android 14+ throws on a location-type FGS without the permission). `requestPermission` sends
  `ACTION_RECHECK` so the type is upgraded.
- **Baseline + secrets while locked.** The baseline blob is AES-GCM encrypted with an Android Keystore
  key created with `setUserAuthenticationRequired(false)`; prefs use `EncryptedSharedPreferences`
  (Keystore-wrapped master key). Both are readable after a reboot without the user unlocking.
- **Audio is never stored.** PCM lives in one `ShortArray`, is classified, zeroed, and dropped.
- **Alarm tone is synthesized** (880 Hz beep on `USAGE_ALARM`, `STREAM_ALARM` at max volume), so no raw
  audio asset is required.
- **dontkillmyapp.** Samsung / Xiaomi / Huawei / OnePlus kill foreground services unless the app is
  excluded from battery optimization and "auto-start" is enabled. `requestPermission('batteryUnrestricted')`
  opens the ignore-battery-optimizations dialog; onboarding should link to https://dontkillmyapp.com for
  the OEM-specific steps. The service returns `START_STICKY`, holds a partial wake lock only during night
  sessions, and uses `setExactAndAllowWhileIdle` for the check-in deadline.

## Sampling modes (CONTRACTS.md §6)

The engine owns the sampling rate; native only executes it.

| Mode | Sensors | Rate | Batching | When |
|---|---|---|---|---|
| **LOW** (default, all day) | `TYPE_LINEAR_ACCELERATION` + `TYPE_GRAVITY`, no gyro | ~10 Hz (`SENSOR_DELAY` 100 000 µs) | `maxReportLatency` 1 s, flushed to `push_motion` once a second | From `SensingService.onCreate`; outside night sessions the engine still needs motion activity/stillness, so LOW never stops while the service runs |
| **FULL** | + `TYPE_GYROSCOPE` (rad/s → `MotionSample.rx/ry/rz`) | 50 Hz (20 000 µs) | same, flush at 50 samples or 1 s | `EngineEvent.SamplingRateChanged { hz, gyro }` with `gyro` or `hz > 15` (engine: away from home 21:00–06:00, or after any incident); also forced natively during a baseline walk, while learning gait on a daytime walk (`learningEnabled` + WALKING), while the dashboard streams and while the telemetry stream is on (`SafetyRuntime.telemetryOn`, default on once configured) |

`SamplingRateChanged` → `SafetyRuntime.samplingFull` → `SensingService.applySampling()` (idempotent; unregisters, flushes,
re-registers). `rx/ry/rz` are 0 whenever the gyro is not registered; `Context.sampling_full` reports what is actually being
delivered. Outside night sessions the day ticker runs `push_context` + `tick` once a minute, or once a second while FULL is
active (no wake lock in day mode, so timing in Doze is best-effort; the sensor hub batches for us). `Context.distance_home_m` is
the haversine distance from the last known fix to the nearest saved home place (-1 when there is no fix or no home); in day
mode the fix is refreshed passively from `fused.lastLocation` once a minute (no active location request).

## Touch / unlock tracking (`Context.last_touch_ms`, `UserAction.PHONE_UNLOCKED`)

Android does not expose system-wide touches to apps (no accessibility service is used), so `last_touch_ms` is a lower bound
assembled from what *is* observable:

1. **In-app touches.** `TouchTracker.attach(activity)` wraps the activity window's `Window.Callback`; every
   `dispatchTouchEvent` (ACTION_DOWN) and `dispatchKeyEvent` updates the timestamp before the view tree sees it. Hooked on
   module `OnCreate`, on every `OnActivityEntersForeground` (the React activity can be recreated), and in `CheckInActivity`.
2. **`ACTION_USER_PRESENT`** (owner dismissed the keyguard) → touch + `push_action(PHONE_UNLOCKED)`.
   **`ACTION_SCREEN_ON`** counts as a touch only when `KeyguardManager.isDeviceLocked` is false — a notification lighting a
   locked screen must not reset the stillness/no-touch clock.
3. **Keyguard transitions.** `isDeviceLocked` is polled from the 1 s night tick, the day ticker and on screen events; a
   locked → unlocked transition also counts as `PHONE_UNLOCKED` (smart-lock / no-credential devices never broadcast USER_PRESENT).
   `PHONE_UNLOCKED` pushes are deduplicated within 3 s.

Limits: touches on the lock screen, in other apps or on the notification shade are invisible (the phone being *used* by
someone else after a grab is therefore not observable — only an unlock is). The value is persisted at most once a minute
(`Prefs.lastTouchMs`) so a process restart does not reset it to 0 (= unknown). Receivers are registered on the application
context from `SafetyRuntime` so tracking works whenever the process is alive, not only while the service runs.

## Dashboard API (CONTRACTS.md §6)

- `getDashboard()` → `{ metrics: LiveMetrics, incidents: IncidentRecord[] }` from `engine.metrics()` / `engine.incidentLog()`
  (newest last; the engine expires entries after 8 h). If the engine is unavailable the native ring buffer of the last 64
  `SignalIncident` records is returned instead.
- `setDashboardStreaming(on)` → a 1 s coroutine ticker in `SafetyRuntime` that emits `dashboard` with the same payload while
  on and a JS listener is attached; stopped on `false` and when the module is destroyed.
- Events: `signalIncident` (one `IncidentRecord`, emitted for every `EngineEvent.SignalIncident`), `callOption` (`{ summary }`,
  after 10 min without a response — native also inserts `incident_events.kind='call_option'` on the current incident and pushes
  to the group with title "No response for 10 minutes"), `dashboard` (see above).
- Serialisation (`EngineMaps.kt`): `u64`/`u32` → JS number via `Long`, `f32` → `Double`, enums → lowercase snake strings
  (`IncidentKind.GAIT_DRIFT` → `"gait_drift"`, `Placement` / `Activity` → `"pocket"`, `"walking"`, …). Field names are the
  Rust names camelCased (`sdDistance`, `rawJson`, `sequenceId`, `baselineWalkDays`).
- Grab path: `HeadsUp` is now also emitted on a grab. Native treats it exactly like a gait heads-up — incident row + push,
  **no** hour-key release and no location; keys are released only on `UnlockLocation` (2 min later unless
  `PHONE_UNLOCKED` / `BIOMETRIC_DISMISS`) or `SnatchDetected`.
- Persistence: the `export_baseline()` blob (baseline + incident log) is saved every 5 min (`EngineHolder.startAutosave`) and on
  night-session stop, config swap, baseline-walk stop, check-in and typing practice.

## Telemetry stream (CONTRACTS.md §7)

`TelemetryPublisher` streams the live engine state to the web monitor over **Supabase Realtime broadcast** — a private
channel, no database rows — on **one persistent WebSocket** (`RealtimeSocket`: OkHttp, Phoenix serializer v2, the same frames
`@supabase/realtime-js` sends). It connects to `wss://{host}/realtime/v1/websocket?apikey={anon}&vsn=2.0.0`, joins
`realtime:telemetry:{userId}` with `{ config: { broadcast: { self, ack: false }, private: true, … }, access_token }`, heartbeats
every 25 s, pushes `access_token` when the JWT rotates and reconnects with 1 / 2 / 5 / 10 s backoff — or immediately when
`SafetyRuntime`'s default-network callback reports connectivity back. A frame is one text frame on the open socket, so the
per-tick cost of the old `POST /realtime/v1/api/broadcast` is gone. The subscriber is unchanged:
`supabase.channel('telemetry:'+uid, { config: { private: true, broadcast: { ack: false } } }).on('broadcast', { event: 'tick' }, cb)`;
`realtime.messages` RLS decides who may publish (the subject) and read (subject + group-mates).

**Rate policy** (re-evaluated every iteration, so night start/stop and the switches need no extra wiring):

| Condition | Rate | Notes |
|---|---|---|
| `telemetryOn` (explicit switch, `setTelemetry`) **or** `dashboardStreaming` | 10 Hz | both also force FULL sampling, **unbatched sensor delivery** (`maxReportLatency = 0`), a partial wake lock (`safe:stream`) and the 1 s day ticker; the channel is joined with `self = true` for the round-trip probe |
| else night mode active | 1 Hz | batched sensors (1 s), no echo |
| else | off | socket closed, the loop idles (1 s poll) |

`telemetryOn` defaults to **true** as soon as `configure()` has run (persisted in `Prefs.telemetryOn`, so `setTelemetry(false)`
sticks across restarts). The engine is still ticked once a second (day ticker / night loop); a frame only drains the rings that
`SensingService` fills per sample (timestamped |a| / |ω|, on its own `safe-sensors` thread) and per tick (engine events), and
attaches the `state` block (`engine.metrics()` + `snapshot()`, no I/O) after each engine tick, at least once a second, and
whenever events / incidents are present. The publisher starts with `SensingService.onCreate` and stops in `onDestroy`;
`setTelemetry(true)` / `setDashboardStreaming(true)` also start it without a service (then it publishes whatever the engine holds).

**Payload** (`v: 2`, camelCase, exact type in §7): every frame carries `t`, `seq`, `user`; `accel` / `gyro` = per-sample |a| (g)
and |ω| (rad/s) since the previous frame, newest last, 4 decimals, capped at 128 (gyro all zeros in LOW mode); `st` = wall-clock
ms of the newest sample; `sampleHz` = measured delivery rate (EMA of sensor-hub timestamps); `incidents` = `IncidentRecord`s with
`id > lastSentId` (the watermark advances when the socket took the frame; every rejoin replays the whole live log once);
`incidentCount`; `events` (snake_case engine events since the previous frame); `rttMs` once measured. `state` = `metrics`,
`hmm`, `escalation`, `riskBand`, `pDanger`, `nightMode`, `battery` (read at most every 10 s), `activity`, `placement`,
`samplingFull`, and `checkPhrase` / `checkDeadlineMs` only while the engine is in `check`.

**Delivery rules.** A frame that fires while the channel is not joined is dropped (counted in `dropped`), never queued. Socket
failures (join refused, `system` error, heartbeat timeout, I/O) increment `failures`, schedule a reconnect and count in
`reconnects`. Logcat tag `Telemetry` gets one line per rate change (`10 Hz (telemetry on)`, `idle …`), per socket state change
(`joined …`, `socket down (…)`, `ok`, `waiting for channel …`), the first echo, and **one summary line a minute**
(`summary: 10 Hz joined=true rtt=61 ms seq=… dropped=… reconnects=… failures=…; token valid 629 s; refresh armed`) — never per
frame. `getTelemetryStatus()` → `{ on, hz, lastSentMs, failures, connected, reconnects, dropped, rttMs, error }` (`on` = the
explicit switch, `hz` = what is actually being published right now).

**Measured on a Nothing A065 (Android 16) against the hosted project:** join 0.4–0.6 s after service start, 10.0 frames/s
sustained, phone → Realtime → phone round trip 30–90 ms (first echo 125–160 ms while the TLS session warms up), stream
unaffected by a forced deep-Doze / "unplugged" period, airplane-mode outage recovered on the first reconnect attempt after
the network returned.

**Session.** The JWT the channel (and every PostgREST call) uses is kept alive by `SessionKeeper` (see CONTRACTS §8): JS hands
over the refresh token, native rotates the pair 5 min before `exp`, pushes the new JWT to the channel and tells JS via
`sessionRefreshed`. Logcat tag `Session`.

**Privacy.** Telemetry carries **no location** — no coordinates, no distance-from-home, no home places. Location stays on the
escrow path (`location_blobs` + `released_keys`). What does go out: gait metrics vs. bands, state probabilities, raw acceleration /
rotation *magnitudes* (not axes), incident summaries, battery, night-mode flag and engine event names.

## Protocol conventions (CONTRACTS.md §5; iOS must match)

| Item | Android implementation |
|---|---|
| `hour_index` | `floor(unix_ms / 3_600_000)` — UTC-absolute hour number (u32), NOT local hour of day; used for `derive_hour_key`, `location_blobs.hour_index`, `released_keys.hour_index` (release = current and next hour) |
| `epoch_id` | `epochs.id` uuid as a lowercase string; `epochs.day` is the local calendar day and K_day rotates at local midnight (same as iOS) |
| `key_shares` AAD | `"share\|{epochId}\|{recipientUserId}"`, plaintext = share bytes, index in `share_index` |
| `released_keys` AAD | `"hour\|{epochId}\|{hourIndex}"`, plaintext = `K_h` |
| `unlock_approvals` AAD | `"approval\|{subjectUserId}\|{epochId}"`, plaintext = `[index u8] ‖ share bytes` |
| `location_blobs.seq` | upload wall-clock unix ms; AAD inside `encrypt_location` is `"{user_id}\|{epoch_id}\|{seq}"` |
| Shamir `k` | `clamp(max(2, threshold_k), 2, n)`; `n` = active members excluding self; `n < 2` ⇒ no shares, fallback unlock disabled |
| group proximity key | `SHA-256(UTF-8 "safe/proximity\|{groupId}\|{YYYY-MM-DD}")` with the date in **UTC** — deterministic so every member derives it; the server can brute-force cells (accepted v1 risk) |
| heartbeat | `PATCH devices?id=eq.{deviceId}` per CONTRACTS §3 (no RPC exists in the schema) |
| check timeout | native schedules an exact alarm at `deadline_ms` and pushes `UserAction.CHECK_TIMEOUT` if still in `EscalationLevel.CHECK` |

## Debug

`injectTrace(json)` (debuggable builds only) replays `{speed, motion[], context[], audio[]}` through the
live engine with timestamps re-based to now; events fire exactly like real ones, so point it at a test
Supabase project. Motion rows may carry `rx/ry/rz` (default 0) and context rows `lastTouchMs` (re-based like `tMs`; 0 =
unknown), `distanceHomeM` (default -1) and `samplingFull` (default true).
